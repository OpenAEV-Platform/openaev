# found; its eagerly fetched domains collection is the gated read, and it comes back empty under the

# BENIGN - roles and marking_definitions activation. The user load of the access check
# (UserService.findWithRoles, from currentUser, currentUserOrNull and userWithRoles) reads the roles
# and the markings of the caller's groups with the request's scope, which is empty for a caller who
# belongs to no tenant (a platform operator, a user a test builds with no membership); a member has
# its tenants in scope. Such a caller holds platform groups only, and a platform group links platform
# roles only (the database refuses a tenant role on it), so the roles it needs are read whatever the
# scope: its capability check passes (ScopedCurrentUserLoadTest, NoMembership and OutsideATransaction,
# the two branches of the load). The markings of its groups are tenant rows and come back empty, but
# nothing reads them from this load: the clearance of a request is read by JDBC from the link table
# (MarkingClearanceCacheManager.findClearance) and neither branch of the load writes the link table
# (CurrentUserLoadUnscopedMarkingsTest). Waived for these two tables only.
io.openaev.service.UserService.findWithRoles tables=roles
io.openaev.service.UserService.findWithRoles tables=marking_definitions
