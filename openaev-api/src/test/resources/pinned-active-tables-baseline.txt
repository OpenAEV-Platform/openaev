# Test classes that set openaev.tenant.active-tables themselves, read by PinnedActiveTablesArchTest.
#
# A class that pins its own list keeps testing the list it was written with. When production
# activates another table, the class does not arm it, so a path through that table runs there with
# no isolation at all while production runs it under the inspector. An isolation test therefore
# follows the production list: ProductionActiveTables in a @DynamicPropertySource, plus its own
# tables on top when it needs more. A class that pins on purpose says why, here.
#
# Format: <fully.qualified.Class> | <pinned tables, sorted> | <kind>: <why, at least six words>
#   The tables column is the list the class pins, "none" for an empty list, or "dynamic" for a
#   @DynamicPropertySource registration that does not read ProductionActiveTables. The guard checks
#   it against the class, so a changed pin brings its reason back under review.
#
# Kinds:
#   probe       every isolation the class asserts is about a table in its list, or it tests a
#               mechanism on the armed set; a table production activates beside it decides nothing.
#   control     leaves a table off on purpose, to show that another mechanism holds on its own.
#   drifts      an assertion depends on the scoping of a table outside its list, so the class tests
#               less than production does. Debt: move it to the production list and delete the line.
#   own-reader  follows production through its own parser. Debt: move it to ProductionActiveTables.
#
# A new probe or control line raises BASELINE_SIZE in review. A drifts or own-reader line is never
# added, and removing one lowers both BASELINE_SIZE and DEBT_SIZE in the same change.
