# Tenant tables not yet activated: the migration burn-down (#8201).
#
# openaev.tenant.active-tables is an allowlist, so a table is isolated only because someone put its
# name in it. TenantTableActivationCoverageArchTest asserts the other direction: every strict tenant
# table the platform knows about is either in that property, or self-isolated with a written reason
# (TenantTables.SELF_ISOLATED_TABLES), or listed here. A table in none of the three fails the build,
# so a new TenantBase entity cannot ship unisolated and unnoticed.
#
# How to read it
#
# One line per table, "<table> | #<issue> | <reason>". The issue is where the activation is tracked
# and carries its owner; the reason says what stands between the table and its activation today. A
# bare table name is rejected: a deferral nobody can explain is not a deferral, it is an omission
# with a nicer name.
#
# Rules of the game
#
# 1. This list only ever SHRINKS. An entry whose table has become active fails the build, so
#    activating a table forces its line out in the same change. Adding a line is how a new table is
#    deferred on purpose, and the diff is the place to argue about it.
# 2. "Not activated yet" is never a reason to put a table in SELF_ISOLATED_TABLES instead. That list
#    is for tables that do not rely on the statement inspector at all, and its javadoc says so.
# 3. When this file holds no entries the rule becomes "every strict tenant table is active", which is
#    the end state #8201 describes, and the activation list itself can go.
#
# Lines starting with # and blank lines are ignored.
