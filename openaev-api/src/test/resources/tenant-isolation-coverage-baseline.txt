# Active tables with no test class marked @CoversTenantIsolation, read by TenantIsolationCoverageArchTest.
#
# The gate requires every table of the production openaev.tenant.active-tables list to be covered by a
# class that is runnable, runs on the real stack, declares the table in its activation list (a probe pin of
# pinned-active-tables-baseline.txt, or a registration of the production list), seeds two tenants and asserts a
# cross-tenant refusal on the table itself: a read, write or delete of the other tenant's row is refused, not
# reached through a parent row. A table that no class meets that bar yet is named here.
#
# A line whose table becomes covered, or stops being active, fails the gate and
# is removed in the same change, and the line count is frozen by TenantIsolationCoverageArchTest.BASELINE_SIZE.
# A line is added only when a review finds that the class marked for a table does not assert the refusal on
# the table itself, and that class loses its marker in the same change. An activation brings its isolation test
# with it.
#
# Format: <table> | <what the existing tests lack> | <why the table is on the list>
#   Where the only class that asserts the table's cross-tenant refusal is a drifts line of
#   pinned-active-tables-baseline.txt, because its flow reads tables the class does not arm,
#   converting that class to follow the production list, and marking it, removes the line here.
organizations | no class on the production list or a probe pin asserts a cross-tenant refusal on organizations | its current classes are drifts lines, and the change that owns the table's activation is the one to convert and mark them
catalog_items | no test seeds two tenants and asserts a cross-tenant refusal on catalog_items | the catalog is read through the connector catalog endpoints, whose isolation test arms connector_instances only
catalog_releases | no test seeds two tenants and asserts a cross-tenant refusal on catalog_releases | the sync endpoint test runs in the default tenant only and asserts release content rules
scope_variables | no class asserts a cross-tenant refusal on scope_variables itself | ChainingHttpIsolationTest runs on the production list and its cross-tenant cases address workflows, steps and conditions; no case asserts on a scope variable row, and the configuration read that loads them is refused on the parent workflow
steps_delay_queue | no class asserts a cross-tenant refusal on steps_delay_queue itself | ChainingHttpIsolationTest runs on the production list and its cross-tenant cases address workflows, steps and conditions; no case asserts on a delay queue row
workflow_scope_rules | no class asserts a cross-tenant refusal on workflow_scope_rules itself | ChainingHttpIsolationTest runs on the production list, but its scope reads resolve the rules into assets, teams and asset groups that are active, so the empty answer under another tenant is produced by those tables as well, and the configuration read and update of the rules are refused on the parent workflow
workflow_states | no class asserts a cross-tenant refusal on workflow_states itself | ChainingHttpIsolationTest runs on the production list and its cross-tenant cases address workflows, steps and conditions; no case asserts on a workflow state row
