# --- Shared-catalog rows written by the lazy per-tenant manager creation inside a background job.
# CredentialConnectivityCheckJobIntegrationTest seeds its tenants with plain SQL, so they were never
# onboarded and have no manager. The job's per-tenant work (validateTenantCredentials, inside
# tenantTx.execute(TxCtx.forTenant(tenantId))) resolves the tenant's secrets provider, which asks
# ManagerFactory for the tenant's manager; ManagerCreator.createManager registers every builtin
# component for that tenant, and the registration creates the missing catalog rows: the collector
# type (CollectorService.ensureCollectorTypeExists), the builtin injector
# (InjectorService.createNewBuiltinInjector) and the phishing landing pages and email templates
# (PhishingLandingPageService.landingPages). Those rows take their tenant from the v1 listener,
# unset on a job thread, so they land in the default tenant while the scope is the tenant being
# served. The same rows are written to the default tenant at tenant onboarding (the
# TenantService.create lines above): the shared catalog lives in the default tenant on every path
# today, and the job's own credential reads and writes are tenant-scoped. Retire these lines with
# the activation of collector_types (#7933) and of the phishing tables (#7901), which decide the
# attribution of that catalog.
