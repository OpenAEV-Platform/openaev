# Write-attribution gate (G1) - waived signatures.
#
# One signature per line: <table> <relation> <entry-frame>, where relation is DEFAULT, OTHER or NULL
# (the written tenant's relation to the request or job scope) and the entry frame is the outermost
# production frame that started the work (class.method, no line number), captured when the
# application asked for the write (persist, merge or load of the entity) or read off the stack of a
# synchronous write. A flush-time write nobody captured, whose flush stack holds no production
# frame, is keyed unattributed(<flushing test>) so that it is visible rather than dropped. Only a
# synchronous write issued by test code itself has no entry frame and is auto-waived (not listed).
#
# Every group names the event that retires it. A line still produced after that event is a finding;
# a line no longer produced is reported stale at the end of an unsharded run and must be removed.
#
# Each signature below was traced and found BENIGN or SCOPED-OK (the write is correctly attributed
# and the flag is an artefact of collection). A signature NOT listed here fails the gate: attribute
# the write from the request's write scope, or add it here with a reason. Wrong-tenant writes that
# are real defects are NOT waived here; they are tracked as findings in the task report.
#
# Lines starting with # and blank lines are ignored. Frozen from one full run of the API suite with the
# nightly shadow arguments (the production active-tables list, both detectors on), which is where the
# gate runs; a line never produced again is reported at shutdown with a [WRITEATTR-STALE] marker. A run
# without the production list can produce signatures that are not listed here, from tests that document
# the behaviour of a table before its activation (a cross-tenant update that the active table refuses).
#
# Every signature below was traced to the test and production path that produced it. None is a live
# cross-tenant write: each is either test-driven provisioning, by-design seeding into the default
# tenant, tenant creation writing the tenant being created, or produced only under a test that arms
# the table inactive. The relevant tables and the follow-up leads are in the task report.
