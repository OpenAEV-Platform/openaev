# Keys whose value space repeats across tenants (#7905).
#
# A join or correlation on one of these columns can match a row owned by another tenant, because the
# same value legitimately exists in several tenants at once. SharedTenantKeyJoinArchTest reads this
# file and fails on any SQL that joins on one of them without constraining both sides to the same
# tenant.
#
# Format, one key per line: <owning_table> <column>
#
# The set is NOT hand-picked. It is derived from the schema by three mechanical rules, and
# SharedTenantKeySchemaCrossCheckTest re-derives it against the live schema and fails when this file
# and the database disagree, so the list cannot rot while the schema moves:
#
#   1. the column is the sole non-tenant_id column of a multi-column UNIQUE index that also includes
#      tenant_id. Uniqueness per tenant is exactly the statement that the value may repeat between
#      tenants. Every other table's primary key is a single column, so a cross-tenant collision on
#      it is structurally impossible and it is not listed here.
#   2. the index names all of its key columns. An index with an expression key (for example
#      LOWER(column)) is skipped, because its real key is not a column list and reading one column
#      out of it invents a key the schema does not have. The cross-check pins the skipped set by
#      name so a new expression index cannot appear unnoticed.
#   3. the column's value space is not globally unique anyway: it is neither a single-column primary
#      key nor a single-column foreign key onto one. This is what keeps users_tenants.user_id and
#      injectors_contracts.injector_contract_payload off the list: both carry values minted by a
#      single-column primary key elsewhere, so the per-tenant unique index over them constrains
#      multiplicity, not identity.
#
# Known gap, deliberate and pinned by the cross-check: a key made of SEVERAL non-tenant columns is
# not listed, because no single column of it is shared on its own. The cross-check asserts the exact
# set of such indexes, so one being added is visible.
#
# Lines starting with # and blank lines are ignored.
