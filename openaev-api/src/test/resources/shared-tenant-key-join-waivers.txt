# The entry names the statement, not a line, so it survives reformatting and goes stale when the
# query it excuses is fixed, renamed or deleted. A stale entry fails the build: the change that
# repairs a query removes its waiver in the same commit, which is what keeps this file from becoming
# a parking lot. "in-subquery" on the right of a key stands for the anonymous result of an
# IN (SELECT ...) correlation.

# The reason must BEGIN with one of these four classifications, spelled out. A bare entry, or one
# whose reason is only a tag, is rejected: an entry must say what makes the join safe, not that it is.
#
#   reaches-active-table:<table> : the join itself is unscoped, but the chain continues onto <table>,
#                             which is on the production active-tables list, so the statement
#                             inspector removes the foreign row before it can reach the result. Name
#                             the table. This reason expires if that table ever leaves the list,
#                             which is why the table is named rather than the effect asserted.
#   dead-code               : the method has no caller. Say how that was established, because the
#                             reason dies the moment somebody calls it.
#   not-established         : the leak is neither proven nor disproven, and no active table
#                             attenuates it. MUST carry an until-active:<table> tag naming the
#                             activation that retires the question, so the entry has an expiry.
#                             Say what measurement would settle it.
#   fixed-pending:#<pr>      : the predicate is repaired on an open pull request that has not landed
#                             yet. Name the pull request. Whichever of the two lands second deletes
#                             these lines, and the stale check above makes forgetting impossible.
